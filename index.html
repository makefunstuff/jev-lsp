jev-lsp

An LSP server. It loads classifier rules from .jev/rules/*.json and publishes normal LSP diagnostics, code actions, and code lens. Not a chat product.

WIP — expect breakage.

What you can do

  • Match lines with a pattern, ask a typed question about each hit
  • Get editor diagnostics when the answer clears the rule floor
  • Use code actions the server exposes
  • Run the same rules via CLI (jev) locally or in CI
  • Point decide at hosted Jev or another compatible endpoint

Setup

  1. Install (Rust ≥ 1.75): 
    cargo install --git https://github.com/makefunstuff/jev-lsp --locked jev-lsp jev
  2. Decide key (hosted default): 
    export TYPESAFE_API_KEY=…
  3. Neovim plugin (repo nvim/, Neovim ≥ 0.12): 
    ln -s /path/to/jev-lsp/nvim ~/.local/share/nvim/site/pack/jev/start/jev
    require('jev').setup({})
    Open a real file, run :checkhealth jev, save.

Other editors: run jev-lsp as a standard LSP server.

Rule example

Create .jev/rules/no-unwrap-in-handlers.json:

{
  "schema": "jev.rules/1",
  "rules": [
    {
      "id": "no-unwrap-in-handlers",
      "title": "Unwrap in a request handler",
      "text": "A handler must not unwrap: a bad request would take the worker down. Return the error instead.",
      "severity": "warning",
      "applies_to": ["**/src/**/*.rs"],
      "inspection": {
        "kind": "regex",
        "pattern": "\\.unwrap\\(\\)"
      },
      "judgement": {
        "question": "Is this unwrap in request-handling code that can fail on bad input?",
        "criteria": {
          "true": "ships in a handler / request path and the value is not proven safe",
          "false": "tests, docs, or an invariant on the surrounding lines covers it"
        },
        "min_probability": 0.85
      },
      "verb_hint": "fix"
    }
  ]
}

Regex selects candidates; Jev only judges those lines. No match → no decide call.
