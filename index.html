jev-lsp

LSP server. Loads rules from .jev/rules/*.json. Publishes normal diagnostics, code actions, and code lens.

WIP. Expect breakage.

What it is

A classifier on matching lines, not a chat model. Pattern hits a line → decide returns a typed value + p → LSP surfaces it if p clears the floor.

What you can do

  • Match lines with a regex (or other inspection)
  • Ask one typed question about each hit
  • See diagnostics in the editor when the answer clears the floor
  • Run the same rules via CLI (jev) or CI
  • Point decide at hosted Jev or a compatible endpoint

Setup

  1. Install (Rust ≥ 1.75): 
    cargo install --git https://github.com/makefunstuff/jev-lsp --locked jev-lsp jev
  2. Decide key (hosted default): 
    export TYPESAFE_API_KEY=…
  3. Neovim (≥ 0.12), plugin from repo nvim/: 
    ln -s /path/to/jev-lsp/nvim ~/.local/share/nvim/site/pack/jev/start/jev
require('jev').setup({})
    Open a real file. :checkhealth jev. Save.

Other editors: run jev-lsp as a normal language server.

Rule example

.jev/rules/no-unwrap-in-handlers.json:

{
  "schema": "jev.rules/1",
  "rules": [
    {
      "id": "no-unwrap-in-handlers",
      "title": "Unwrap in a request handler",
      "text": "A handler must not unwrap: a bad request would take the worker down. Return the error instead.",
      "severity": "warning",
      "applies_to": ["**/src/**/*.rs"],
      "inspection": {
        "kind": "regex",
        "pattern": "\\.unwrap\\(\\)"
      },
      "judgement": {
        "question": "Is this unwrap in request-handling code that can fail on bad input?",
        "criteria": {
          "true": "ships in a handler / request path and the value is not proven safe",
          "false": "tests, docs, or an invariant on the surrounding lines covers it"
        },
        "min_probability": 0.85
      },
      "verb_hint": "fix"
    }
  ]
}

Regex picks candidates. Jev judges only those lines. No match → no decide call.
